在使用网络连接服务与各类客户端（Clash Verge、Sing-box、Shadowrocket、v2rayN）的过程中，最令人头疼的问题莫过于：**客户端界面显示节点延迟 50ms、主开关已开启，但打开浏览器却网页打不开、提示连接超时或无法联网**。

作为「晚风机场服务指南」的故障排查专题，本文将拆解导致“假连接”的 **5 大底层原因**，并提供一套高效率的排除诊断流程。

---

## 1. 故障排查逻辑决策树

遇到断网问题时，切忌盲目乱改设置。建议按照以下顺序逐步筛选原因：

```
[故障发生]
 ├─ 1. 本地系统时间是否精准？ ──（否）──> 开启系统自动对时 ──> [恢复正常]
 ├─ 2. 订阅节点 IP 是否过期？ ──（是）──> 一键更新订阅链接 ──> [恢复正常]
 ├─ 3. 系统代理/TUN 模式是否被占用？ ──（是）──> 重置代理与虚拟网卡 ──> [恢复正常]
 ├─ 4. DNS 发生污染或解析失败？ ──（是）──> 切换预设 DNS 地址 ──> [恢复正常]
 └─ 5. 服务商线路晚高峰遭遇运维中断 ──> 切换备用服务商节点
```

---

## 2. 5 大常见断网原因与解决办法

### 原因 1：系统时间未对准（时间同步误差 > 60 秒）
* **原理**：绝大多数现代传输协议（如 VMess, VLESS, Trojan, Hysteria 2）采用强时间戳加密保护。如果你的设备本地时间与标准 GMT 时间相差超过 60 秒，服务端会直接拒绝数据握手。
* **解决办法**：
  - **Windows**：打开 `设置 -> 时间和语言 -> 日期和时间`，点击 **立即同步**。
  - **macOS / iOS / Android**：在系统设置中确保开启了 **自动设置时间**。

---

### 原因 2：订阅节点信息失效（服务商更换了出口 IP）
* **原理**：服务商如果更换了服务器出口 IP，而你本地客户端依然在使用缓存的旧 IP 列表，就会出现假连接。
* **解决办法**：
  - 在客户端中找到订阅名称，点击 **更新订阅 (Update Subscription)**。

---

### 原因 3：系统代理端口占用或未接管
* **原理**：客户端虽然启动了，但 Windows/macOS 的系统代理设置没有成功指向客户端监听的本地端口（如 `127.0.0.1:7897` 或 `10809`）。

| 操作系统 | 系统代理检查路径 | 恢复标准设置 |
| :--- | :--- | :--- |
| **Windows 11** | 设置 -> 网络和 Internet -> 代理 | 关闭手动代理，或重新勾选客户端的“系统代理” |
| **macOS** | 系统设置 -> 网络 -> 代理 | 确认 HTTP/HTTPS 代理已正确勾选 |

---

### 原因 4：DNS 解析污染与缓存失真
* **原理**：本地电脑缓存了被污染的域名 IP 解析结果，导致流量无法被正确分流路由。
* **解决办法**：
  - 清理本地系统 DNS 缓存：
    ```cmd
    # 在 Windows 命令提示符 (CMD) 中执行：
    ipconfig /flushdns
    ```
  - 在 Clash / Sing-box 客户端设置中，将内建 DNS 修改为安全的加密 DNS：
    ```yaml
    dns:
      nameserver:
        - 223.5.5.5
        - 1.1.1.1
        - https://dns.alidns.com/dns-query
    ```

---

### 原因 5：安全软件（防火墙 / 杀毒软件）阻断
* **原理**：部分杀毒软件把客户端建立的 TUN 虚拟网卡误判为非法网卡并进行了拦截。
* **解决办法**：将 Clash Verge 或小火箭加入安全软件的信任白名单中。

---

## 3. 常见报错信息速查表

```
NET::ERR_PROXY_CONNECTION_FAILED ──> 本地代理端口不匹配或客户端意外崩溃
NET::ERR_CERT_DATE_INVALID       ──> 本地系统时间严重偏差
TLS Handshake Timeout             ──> 服务商节点 IP 被封锁或晚高峰线路丢包率极高
DNS_PROBE_FINISHED_NXDOMAIN       ──> 本地 DNS 解析失效
```

---

## 4. 总结与日常自检流程

面对“节点已连接却无法上网”的问题，记住 **“时间第一、更新第二、代理第三、DNS 第四”** 的排错口诀。按顺序自检 95% 以上的网络断连故障均可顺利解决。
