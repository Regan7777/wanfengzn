在使用网络服务商（机场）时，不少新手常常遇到这样的困扰：手动挑选的节点在白天速度飞快，一到晚上 8 点至 11 点的晚高峰，节点忽然变得卡顿甚至丢包超时。

手动频繁点开客户端寻找可用节点不仅繁琐，而且极易打断工作流。

通过在客户端中配置 **URL-Test 自动选择策略组** 与 **Fallback 故障转移组**，可以实现**“自动检测最低延迟节点 + 节点宕机无感自动自愈”** 的流畅体验。

本教程将详细剖析节点延迟测速的底层原理，并指导如何在 Clash、Sing-box、Shadowrocket 等主流客户端中开启自动化切换。

---

## 1. 测速原理：Ping 延迟 vs HTTP 真实连通延迟

在客户端界面点击“批量测速”时，返回的数字（如 `45ms` 或 `520ms`）代表什么？

```
代理链路测速两段式结构：
你的电脑 ──(第 1 段: 中转入口)──► 机场入口服务器 ──(第 2 段: 专线/公网)──► 出口节点 ──► 目标网站
                 ▲                                                         ▲
         传统的 Ping 仅测第一段                                 HTTP 测速测完整全程
```

- **TCP Ping / ICMP 测速**：仅测量电脑到中转入口的延迟。即便入口响应极快（如 15ms），若中转到海外出口断连，页面依然打不开（俗称“假延迟”）。
- **HTTP/URL 测速（推荐）**：客户端向指定的测试网址（如 `http://cp.cloudflare.com/generate_204`）发送真实的 HTTP 请求，测量从发起连接到收到响应头部的**完整端到端时延**。

## 2. 配置 URL-Test 自动选择策略组

**URL-Test** 策略组会在后台按照设定周期向多个节点发起 HTTP 测速，并**自动将流量调度到响应时间最短的节点**。

```yaml
# 典型 Clash / Mihomo 内核策略组配置示例：
proxy-groups:
  - name: 🚀 节点自动选择
    type: url-test
    url: http://www.gstatic.com/generate_204
    interval: 300     # 每 300 秒 (5分钟) 自动测速一次
    tolerance: 50     # 延迟容差 50ms（只有新节点比当前节点快 50ms 以上才切换，防止频繁跳动）
    proxies:
      - 香港 IEPL 01
      - 香港 IEPL 02
      - 日本 BGP 01
      - 新加坡 01
```

### 操作指南：
1. **Clash Verge Rev**：在 `代理 (Proxies)` 页面顶部，找到名为 `自动选择` 或 `Auto` 的策略组卡片，勾选该策略组作为默认出口。
2. **Shadowrocket**：在主界面路由点击 `配置` -> 点击当前配置文件 -> 选择 `添加策略组` -> 类型选择 `url-test` -> 勾选所有主力节点。
3. **Flclash**：在代理组列表中选择带有 `⚡ 自动` 标识的分组。

## 3. 配置 Fallback 故障自愈策略组

与 URL-Test 追求“最低延迟”不同，**Fallback（故障转移）** 策略组的目标是**“保障 100% 不掉线”**。

- **工作机制**：策略组会按你设定的节点优先级（顺序 1 -> 顺序 2 -> 顺序 3）依次使用。只要节点 1 正常连通，就始终使用节点 1；一旦节点 1 触发超时故障，瞬间无感切换到节点 2。
- **适用场景**：适合正在进行 **Zoom 跨国视频会议、在线直播、外服游戏或文件下载** 等不能容忍 IP 频繁变动的场景。

## 4. 晚高峰丢包自愈与最佳实践技巧

在每天 20:00 - 23:00 的公网拥堵期，如何保障连接质量？

```
晚高峰优选策略链：
[选择专线节点] -> [设置 300s 测速周期] -> [设置 50ms 切换容差] -> [锁定 AI/金融平台节点]
```

1. **优先使用 IEPL/IPLC 专线节点**：在自动选择策略组中，取消勾选易受公网干扰的“普通直连”节点，仅保留 `IEPL` 或 `IPLC` 专线节点。
2. **合理设置切换容差 (Tolerance)**：将容差建议设为 **`50ms - 100ms`**。如果容差过小（如 5ms），稍微的抖动就会引发节点频繁切换，导致部分网页登录凭证（Cookies）失效。
3. **分场景隔离策略**：
   - **流媒体/日常浏览**：使用 `URL-Test 自动选择` 追求速度；
   - **ChatGPT / Claude / 银行 App**：使用 `固定代理节点` 锁定纯净 IP，避免触发风控防刷机制。

## 5. 常见问题 FAQ

### Q1: 手动批量测速时提示“测试失败”或超时，但单个节点点开又能用？
**答**：某些服务商后台设置了高频并发防御，短时间内并发请求几十个节点测速会被防火墙拦截。建议在客户端设置中降低并发测试数量，或延长自动测速的间隔时间。

### Q2: 为什么测速 URL 推荐使用 `generate_204`？
**答**：`http://www.gstatic.com/generate_204` 是谷歌官方提供的轻量级连通测试点，成功连通时只返回 `204 No Content` HTTP 状态码，数据量极小（几十字节），既不消耗套餐流量，又能精准反映节点连通状态。
