# 网络服务博客内容写作与 GEO / SEO 规范指南

本文档为后续内容创作者、编辑团队及 AI 内容生成工具提供写作规范。所有新创作的中文文章与专题页均应遵循本指南。

---

## 1. 文章结构规范 (Article Structure)

### 1.1 搜索意图与层次结构
* **H1 标题：** 每篇文章必须且只能有一个 `<h1>` 标题，必须自然包含核心搜索词（如：`2026机场推荐`、`IEPL专线`、`月付套餐`）。
* **正文结构：** 正文从 `<h2>` 开始，小节采用 `<h3>`。不得越级使用标题（如在 `<h2>` 下直接使用 `<h4>`）。
* **开门见山（直接回答）：** 文章开头推荐包含 **核心结论 / TL;DR (Quick Answer)** 模块，帮助用户和 AI 搜索系统（GEO）瞬间获取关键答案。

### 1.2 标准推荐结构
1. **核心答案 / TL;DR (1-2段)**
2. **背景与定义（是什么）**
3. **深入解析与对比（为什么 / 怎么选）**
4. **具体操作步骤与避坑细节（如何做）**
5. **对比表格 / 参数表**
6. **常见问题解答 (FAQ 模块)**
7. **相关延伸阅读链接**

## 3. SEO 与 GEO 优化要点

1. **Title 与 H1 差异化：** Title 可以包含品牌后缀 ` - 网络服务选择指南`，H1 聚焦文章核心问题。
2. **Meta Description：** 控制在 100-150 字之间，精准概括文章解决的问题。
3. **图片 Alt 属性：** Alt 必须真实描述图片展示的信息（如 `alt="2026机场线路对比表"`），切忌机械堆砌关键词。
4. **表格与数据化展示：** 尽可能使用 Markdown 表格呈现对比数据，方便搜索系统抓取表格结构。
5. **内链互联：** 并在正文中通过自然上下文提及其他相关专题或 Pillar 页面，形成完整网状架构。

## 4. 代码与变量中性命名规范

为了保证开发代码库在长期维护与 CI/CD 构建中的稳定性，在：
* 代码文件名
* 组件命名
* 变量与 TypeScript 接口定义
* 开发注释

中尽量使用以下中性术语：
`网络服务`, `连接服务`, `线路服务`, `网络工具`, `节点服务`, `服务商`, `连接方案`, `网络环境`, `网络线路`, `服务评测`

在公开 Markdown 页面及展示给搜索用户的 HTML 文本中，正常使用用户实际搜索关键词（如 `机场推荐`、`2026机场推荐`、`稳定机场` 等）。
